# AlertForge evaluation dataset v1 (frozen)

Fixed before any rule or threshold was measured against it. Files in `data/eval/`:

| File | Content |
|---|---|
| `dataset-v1.log` | 5,766 web access log lines (Apache/Nginx combined format), chronological |
| `dataset-v1-labels.csv` | one row per log line: `line_no, source_ip, label, scenario, variant, episode_id, alert_expected, expected_rule` |
| `dataset-v1-manifest.txt` | counts and SHA-256 hashes; the evaluation runner refuses to run if a file changed |

Generated by `scripts/generate_dataset.py` (seed 20261125). Never regenerate; the committed files are the test set.

## Composition

An **episode** is one attack, one look-alike normal case or one background user. Every episode has its own
source IP, so each alert can be assigned to exactly one episode.

| Scenario | Kind | Episodes | Requests | Expected rule | Variants |
|---|---|---|---|---|---|
| brute_force | attack | 30 | 289 | AF-001 | fast 20, medium 5, slow 5 (gap between failed logins) |
| vuln_scanner | attack | 30 | 249 | AF-002 | sqlmap, nikto, nmap-nse, nuclei, wpscan, openvas (5 each) |
| dir_scanner | attack | 30 | 449 | AF-006 | gobuster, ffuf, feroxbuster, wfuzz, dirbuster (6 each) |
| sqli | attack | 30 | 30 | AF-003 | one payload from public lists per episode |
| xss | attack | 30 | 30 | AF-004 | one payload from public lists per episode |
| id_enum | attack | 30 | 881 | AF-005 | fast 20, medium 5, slow 5 (gap between ID requests) |
| background | normal | 40 | 3,000 | none | 40 simulated users, 75 requests each |
| lookalike_brute_force | normal | 30 | 170 | none | few typos 10, four failures 10, failures spread out 10 |
| lookalike_sqli | normal | 30 | 30 | none | harmless searches with SQL-like words or characters |

Totals: 370 episodes (180 attack, 190 normal), 1,928 attack requests, 3,838 normal requests.

## Labels

`alert_expected` is 1 for every record of an attack episode and 0 for every record of a normal episode.
Threshold rules alert on the burst, not on each request, so the expectation is per episode: an attack
episode must produce at least one alert from `expected_rule`; a normal episode must produce none.

## Metrics (episode level)

* Detection rate = attack episodes with an alert from the expected rule / attack episodes.
* False-positive rate = normal episodes with at least one alert / normal episodes.
* Precision = detected episodes / (detected episodes + false-positive episodes).
* Also reported: alerts on normal traffic per 1,000 normal requests, and the missed / false-positive episodes.

## Notes on honesty

* Payloads come from public SecLists files (see `payloads/SOURCES.md`), not from our regular expressions.
* Look-alike cases were written without looking at the rules; some may trigger them, and that is a result.
* Slow and near-threshold variants are included on purpose: they show what a given threshold misses or over-alerts.
* If a rule is changed after seeing these results, report the numbers before and after the change, and say that
  the second number was measured on data the rule was already tuned against.

## Dataset v2 (held-out check, added after the first evaluation)

After the first evaluation of v1, rules AF-002, AF-003 and AF-004 were improved using what the missed
episodes showed. v1 can no longer judge those improvements independently, so a second set was generated:

| | v1 | v2 |
|---|---|---|
| Files | `dataset-v1*` | `dataset-v2*` (log, labels, manifest) |
| Seed | 20261125 | 20261127 |
| Requests | 5,766 (3,838 normal, 1,928 attack) | 5,769 (3,850 normal, 1,919 attack) |
| Episodes | 370 (180 attack, 190 normal) | 370 (180 attack, 190 normal) |
| SQLi / XSS payloads | 30 + 30 from SecLists | 30 + 30 **different** payloads from the same SecLists lists (`sqli-v2.txt`, `xss-v2.txt`) |
| Look-alike searches | v1 lists | new lists, written independently of v1 and of the rules |

Generated with `python scripts/generate_dataset.py --v2` after `python scripts/select_payloads.py <folder> --v2`.
The v2 files were frozen before the improved rules were measured against them.

Limits of v2 as an independent test: it uses the same generator structure (the same attack tempos and
thresholds-related variants), the same scanner tool list, and payloads from the same source lists. It checks
that the AF-003 / AF-004 changes generalise to unseen payloads and new benign searches; it does not
independently test AF-002 / AF-006 (same tools) or the threshold sweeps (same variant design).
